# Готовое задание для Codex / OpenCode — Legal AI Companion

**Режим:** PHASED. В этой сессии разрешена **только фаза 1** (работающий mock-MVP расширения). Внутри фазы действуй небольшими STANDARD-изменениями. Не переходи к OpenAI API, авторизации или ГАРАНТ Коннект без нового задания.

> **Этот документ самодостаточен.** Он применим даже в папке, где нет `AGENTS.md`, `README.md`, `plan.md` или каталога `docs`. Не останавливайся из-за отсутствия этих файлов и не выдумывай их содержимое. Если другие документы существуют, используй их после проверки их актуальности по репозиторию.

## 1. Цель и контекст

Создать **Legal AI Companion by snetkov.ru** — небольшое кроссбраузерное расширение, добавляющее панель правового ИИ-помощника в веб-версию справочно-правовой системы «ГАРАНТ» (`https://internet.garant.ru/*`). Целевые браузеры: Chrome, Opera, Firefox и Яндекс Браузер.

В будущем продукт должен поддерживать ChatGPT/OpenAI, пользователей с различными тарифами и, отдельно, разрешённые запросы к ГАРАНТ Коннект. Но **сейчас реализуется только локальный демонстрационный интерфейс, без сетевых запросов к ИИ и правовой базе**. Codex/OpenCode — средства разработки, **не** конечный ИИ-движок продукта.

Следуй правилу **Strategy → Task → Diff**: сначала установи реальное состояние проекта, затем выполни минимальное полное изменение и проверь только затронутые сценарии.

## 3. Неопределённости и границы

- Не гарантируется доступ к авторизованной веб-версии ГАРАНТа. Если доступа нет, работай с локальным HTML fixture, а реальную интеграцию отметь как **NOT RUN**, не как PASS.
- Совместимость Opera/Яндекс Браузера не подтверждается одним успешным Chromium build; Firefox требует отдельной проверки.
- Реальные условия доступа к OpenAI Sign in with ChatGPT и ГАРАНТ Коннект пока не являются частью фазы 1. Не обещай функциональность на основании названия тарифа пользователя.
- Не менять архитектуру действующего проекта без обоснования; предпочтение существующему стеку, если он пригоден.
- Нельзя обходить аутентификацию ГАРАНТа, его CSP или ограничения лицензии; нельзя использовать недокументированные закрытые endpoints.

## 6. Минимальный объём изменений

Реализуй следующее на выбранном/существующем минимальном стеке (предпочтительно TypeScript + WebExtensions Manifest V3):

1. **Host scope:** content script только для согласованного веб-домена `internet.garant.ru` по HTTPS. Не запрашивай разрешения `<all_urls>` или ненужные browser permissions.
2. **UI:** одна ненавязчивая кнопка открытия/закрытия панели; Shadow DOM для изоляции панели от стилей ГАРАНТа; CSS в отдельном файле; корректная работа при узком окне.
3. **Selection:** пользователь вручную выделяет текст и явно вызывает захват; показать выбранный текст/предпросмотр. Если ничего не выбрано — понятная ошибка. Лимит **12 000 символов** с явным сообщением (не скрытое обрезание).
4. **Consent:** только после просмотра фрагмента пользователь нажимает «Отправить». Не собирать весь документ, не отслеживать выделения для отправки и не отправлять их автоматически.
5. **Demo mode:** локальный детерминированный mock-provider, не выполняющий никаких сетевых запросов. Обязательная маркировка ответа: **«Демонстрационный ответ. Правовые нормы не проверялись»**. Не имитировать проверку закона/судебной практики и не выдавать вымышленные ссылки.
6. **Reliability & accessibility:** не создавать дубликаты панели при повторной инициализации; обрабатывать SPA-навигацию и устаревший контекст; поддерживать Tab, видимый focus, Escape, доступные подписи контролов.
7. **Cross-browser:** предусмотреть реальные сборки для Chromium и Firefox. Один общий код, точечные manifest/background адаптеры по необходимости. Для Opera и Яндекс Браузера подготовить инструкции ручной проверки, не объявляя неподтверждённую совместимость.
8. **Security:** выводить сторонний текст через `textContent`/безопасный рендер; никакого `innerHTML` из выделения; никакого доступа к cookie ГАРАНТа; не хранить токены и выделенный текст постоянно; никаких внешних сетевых запросов, телеметрии и скрытой аналитики.
9. **Tests:** покрыть выбор/предпросмотр/submit, отсутствие выделения, превышение лимита, дубли, разрешённый хост, небезопасный HTML-текст, очистку устаревшего контекста и отсутствие сетевых запросов в demo mode. Используй существующий тестовый стек; не внедряй тяжёлую инфраструктуру.

Не создавать сервер, БД, Native Messaging bridge, OpenAI SDK, OAuth, provider registry, ChatGPT authentication, ГАРАНТ API/MCP или историю диалогов в этой фазе.

## 7. Выходные артефакты

- Краткая инструкция установки/тестирования. Если нет README, допустимо создать **минимальный README.md** без большого набора вспомогательных документов.

- Если существуют `plan.md`/`CHANGELOG.md`, обнови только актуальные пункты; не создавай пустые формальные документы.

## 8. Проверяемые критерии приёмки

- AC-01: панель внедряется только на разрешённом домене.
- AC-02: кнопка показывает/скрывает одну панель; нет повторных экземпляров.
- AC-03: панель изолирована стилями и не ломает страницу (где это проверено).
- AC-04: явный выбор фрагмента → видимый предпросмотр; нет автоматической отправки.
- AC-05: пустое выделение и текст более 12 000 символов обрабатываются корректно.
- AC-06: «Отправить» выдаёт только локальный mock-ответ с явной маркировкой.
- AC-07: сайт не получает от расширения скрытых сетевых запросов/данных.
- AC-08: небезопасный текст отрисовывается как текст, не исполняется.
- AC-09: Tab/Escape, focus, адаптивность и смена документа проверены по доступной среде.
- AC-10: сборки Chromium и Firefox проходят; реальные браузерные smoke-тесты отмечены отдельно.
- AC-11: исходные Git-изменения пользователя сохранены; никаких неожиданных операций.

**Окончание фазы 1:** пользователь выбирает текст на разрешённой странице (или в согласованном тестовом fixture), видит предпросмотр, вручную отправляет, получает маркированный локальный ответ; доступные проверки выполнены и ограничения раскрыты.

## 9. Проверки, безопасность и риски

Запусти релевантные команды, **которые действительно существуют** после проверки репозитория: typecheck, lint, unit tests, Chromium/Firefox build, `git diff --check`, review manifest permissions, поиск случайных секретов/сетевых вызовов; ручные browser smoke-тесты только там, где реально доступен браузер.

Не подменяй manual smoke успешной сборкой. Все проверки в отчёте должны быть `PASS`, `FAIL` или `NOT RUN` с конкретной командой или способом проверки и причиной. Если Git отсутствует, git-проверки отмечай `NOT RUN`.

Ключевые риски: интеграция с недоступным UI ГАРАНТа, CSP/SPA-навигация, несовместимость Firefox/Chromium, инъекция HTML, скрытая передача конфиденциального текста, избыточные разрешения, недостоверная маркировка демонстрационных выводов.

## 10. Запреты

Без нового прямого указания владельца **не выполнять** `commit`, `push`, `merge`, `rebase`, `reset --hard`, `clean`, переключение/удаление веток или worktree, `deploy`, публикацию, деструктивные операции, удаление чужих файлов и изменение других репозиториев. Не тратить деньги на внешние API; не получать/вставлять реальные токены; не сохранять секреты в логах, промптах или сборках. Не делать массовую выгрузку юридических текстов.

## 11. Формат итогового отчёта

**A. Strategy → Task → Diff:** цель, фактически решённая задача и минимальное итоговое изменение.

**B. Baseline:** каталог, наличие Git, branch/HEAD (если есть), исходный `git status`, обнаруженные ранее изменения.

**C. Files:** все созданные/изменённые файлы и назначение; что оставлено вне фазы.

**D. Checks:** таблица `Проверка | Команда/метод | PASS/FAIL/NOT RUN | Фактический результат/ограничение` для typecheck, lint, tests, builds, browser smoke, security review и git diff check.

**E. Acceptance:** AC-01…AC-11 с проверяемым основанием; `NOT VERIFIED` там, где доказательств нет.

**F. Risks:** остаточные ограничения, недоступные внешние сервисы, неподтверждённая совместимость и несделанные проверки.

**G. Git:** итоговый `git status`, diff summary и подтверждение сохранения исходных изменений; указать, что commit/push/merge/deploy не делались.

**H. Decision:** `PASS` / `PASS WITH ACCEPTED RISK` / `FAIL` **только для проверенного объёма фазы 1**, один следующий рекомендуемый шаг.

**После отчёта остановись. Не начинай следующую фазу самостоятельно.**
